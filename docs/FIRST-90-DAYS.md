# First 90 days

The plan shown in [Operating Cadence](https://cashpointsoulja.github.io/runtime-ops-desk/cadence/). Every outcome is measurable; every target is a proposal, not a Runtime commitment.

## Days 1-30

| Do | Measured by |
| --- | --- |
| Ship the first five internal agents from the Automation Map build order (support triage first). | 5 agents live with approvals on; each has a written success measure and a weekly pass rate. |
| Run the first customer health review across every account. | Every account has a health score with ≥ 60% coverage and a named next action. |

## Days 31-60

| Do | Measured by |
| --- | --- |
| Send the first board and investor update from the Operating Cadence builder. | Update sent on the agreed date; every number traces to a source system. |
| Close the first product feedback cycle: Friction Log reviewed with engineering. | Top 3 items have an owner and a ship date; at least 1 shipped. |

## Days 61-90

| Do | Measured by |
| --- | --- |
| Renewal briefs for every account renewing in the next two quarters. | Brief sent 90 days before each renewal; renewal risk agreed with founders. |
| Hand off agent ownership: each internal agent has an owner and a monthly review. | Weekly hours saved reported against the Automation Map estimate. |

## How each item maps to a module

- Five internal agents: [Automation Map](https://cashpointsoulja.github.io/runtime-ops-desk/automation/) build order, weeks 1 to 4.
- First health review: [Customer Desk](https://cashpointsoulja.github.io/runtime-ops-desk/customers/) health model and weekly actions.
- First board update: [Operating Cadence](https://cashpointsoulja.github.io/runtime-ops-desk/cadence/) board update builder.
- First product feedback cycle: [Run Review](https://cashpointsoulja.github.io/runtime-ops-desk/review/) Friction Log and weekly digest.
- Renewal briefs: [Customer Desk](https://cashpointsoulja.github.io/runtime-ops-desk/customers/) QBR brief export.
